TQ Bank API

REST API for customer registration, accounts, deposits, withdrawals, transfers and transaction history. Version 1.0.0. This reference describes the expected behaviour of every endpoint, in line with the SRS. Use it as the oracle when you test.

Base URL

http://localhost:8080/api

Authentication

Call POST /auth/login, then send Authorization: Bearer <token> on every endpoint except register, login and logout.

Login then call an endpoint
curl -X POST "http://localhost:8080/api/auth/login" -H "Content-Type: application/json" -d '{"identifier":"nour@mail.com","password":"Strong@123"}'

curl "http://localhost:8080/api/accounts" -H "Authorization: Bearer <token>"

Conventions

  • All request and response bodies are JSON (Content-Type: application/json), except the CSV export.
  • Amounts are JSON numbers in EGP with at most 2 decimal places.
  • Dates use YYYY-MM-DD; timestamps use YYYY-MM-DD HH:mm:ss.
  • Ids in the path are integers; account numbers are 10-digit strings.

Authentication

POST/auth/registerPublic

Register a customer

Creates a new customer account. Passwords are stored hashed. The new customer can log in immediately.

Parameters

NameInTypeRequiredRules
fullNamebodystringyesLetters and spaces only, 3-50 characters.
emailbodystringyesValid email format (user@domain.com). Must be unique (case-insensitive).
phonebodystringyesExactly 11 digits starting with 010, 011, 012 or 015. Must be unique.
dateOfBirthbodystringyesFormat YYYY-MM-DD. Must be in the past. Customer must be 18 or older.
passwordbodystringyes8-20 characters with at least 1 uppercase, 1 lowercase, 1 digit and 1 special character (!@#$%^&*).
confirmPasswordbodystringyesMust be identical to password.

Errors

StatusMessageWhen
400Full name must be 3-50 alphabetic characters.fullName invalid
400Invalid email format.email invalid
400Phone must be 11 digits starting with 010, 011, 012 or 015.phone invalid
400Invalid date of birth. Use YYYY-MM-DD.dateOfBirth not parseable
400Date of birth must be in the past.dateOfBirth today or future
400You must be at least 18 years old.customer younger than 18
400Password must be 8-20 chars with uppercase, lowercase, digit and special character (!@#$%^&*).password rule violated
400Passwords do not match.confirmPassword differs
409Email already registered.email exists
409Phone number already registered.phone exists
Request
curl -X POST "http://localhost:8080/api/auth/register" \
  -H "Content-Type: application/json" \
  -d '{"fullName": "Nour Hassan", "email": "nour@mail.com", "phone": "01012345678", "dateOfBirth": "2000-04-12", "password": "Strong@123", "confirmPassword": "Strong@123"}'
Response 201
{
  "message": "Registration successful."
}
Error example 400
{
  "status": 400,
  "error": "Full name must be 3-50 alphabetic characters."
}
POST/auth/loginPublic

Log in

Authenticates a customer or admin and returns a bearer token. Three consecutive failed attempts lock the account for 15 minutes. A successful login resets the failed-attempt counter.

Parameters

NameInTypeRequiredRules
identifierbodystringyesEmail address or phone number.
passwordbodystringyesAccount password.
  • Send the token on every other request as the header Authorization: Bearer <token>.
  • A session expires after 15 minutes of inactivity (401 "Your session has expired. Please log in again.").

Errors

StatusMessageWhen
400Email/phone and password are required.identifier or password empty
401Invalid email/phone or password.unknown user OR wrong password (same message for both)
423Account locked due to multiple failed attempts. Please try again in 15 minutes.3rd consecutive failure, and any attempt while locked
Request
curl -X POST "http://localhost:8080/api/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"identifier": "nour@mail.com", "password": "Strong@123"}'
Response 200
{
  "token": "3f1c0b8e-6d52-4c1e-9a77-1c2b9d0a4e55",
  "userId": 2,
  "fullName": "Nour Hassan",
  "role": "CUSTOMER"
}
Error example 400
{
  "status": 400,
  "error": "Email/phone and password are required."
}
POST/auth/logoutPublic

Log out

Ends the session. After logout the token must no longer be accepted by any endpoint.

Parameters

No parameters.

  • Expected: calling any protected endpoint with the old token returns 401.
Request
curl -X POST "http://localhost:8080/api/auth/logout"
Response 200
{
  "message": "Logged out successfully."
}

Accounts

POST/accountsCustomer token

Open a new account

Opens a Savings or Current account for the logged-in customer. The opening balance is recorded as the first DEPOSIT transaction. The account number is auto-generated (10 digits, unique).

Parameters

NameInTypeRequiredRules
accountTypebodystringyesSAVINGS or CURRENT.
openingBalancebodynumberyesBetween 100 and 1,000,000 EGP, at most 2 decimal places.

Errors

StatusMessageWhen
400Account type must be SAVINGS or CURRENT.invalid accountType
400Invalid amount format.missing, non-numeric or more than 2 decimals
400Opening balance must be at least 100 EGP.openingBalance < 100
400Opening balance cannot exceed 1,000,000 EGP.openingBalance > 1,000,000
400Maximum of 5 accounts reached.customer already has 5 accounts
401Authentication required.missing token
Request
curl -X POST "http://localhost:8080/api/accounts" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"accountType": "SAVINGS", "openingBalance": 500}'
Response 201
{

  "accountNumber": "4829105736",
  "accountType": "SAVINGS",
  "balance": 500.0,
  "status": "ACTIVE",
  "referenceId": "#TX-3FA91"
}
Error example 400
{
  "status": 400,
  "error": "Account type must be SAVINGS or CURRENT."
}

Transactions

POST/accounts/{id}/depositCustomer token

Deposit money

Adds money to one of your accounts. New balance = old balance + amount. Frozen accounts reject deposits. A rejected deposit changes nothing.

Parameters

NameInTypeRequiredRules
idpathintegeryesAccount id (must be yours).
amountbodynumberyesGreater than 0 and at most 50,000 EGP per transaction (50,000 is allowed). Max 2 decimal places.

Errors

StatusMessageWhen
400Invalid amount format.missing, non-numeric or more than 2 decimals
400Amount must be greater than zero.amount <= 0
403Access denied.account belongs to another customer
404Account not found.unknown id
422Deposit amount cannot exceed 50,000 EGP per transaction.amount > 50,000
422Account is frozen. Transactions are not allowed.account status FROZEN
Request
curl -X POST "http://localhost:8080/api/accounts/1/deposit" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"amount": 1000}'
Response 200
{
  "referenceId": "#TX-7C21E",
  "type": "DEPOSIT",
  "accountNumber": "1000000001",
  "amount": 1000.0,
  "balanceAfter": 5500.0,
  "dateTime": "2026-10-18 21:30:05"
}
Error example 400
{
  "status": 400,
  "error": "Invalid amount format."
}

POST/transfersCustomer token

Transfer between accounts

Moves money from one of your accounts to any account number. The debit and credit succeed together or fail together. Two history records are created that share one reference id: TRANSFER_OUT (source) and TRANSFER_IN (destination).

Parameters

NameInTypeRequiredRules
fromAccountIdbodyintegeryesYour source account id.
toAccountNumberbodystringyesDestination account number, exactly 10 digits.
amountbodynumberyesGreater than 0 and at most 25,000 EGP. Max 2 decimal places.
notebodystringnoUp to 50 characters.

Errors

StatusMessageWhen
400Source account is required.fromAccountId missing
400Invalid account number.toAccountNumber is not 10 digits
400Invalid amount format.missing, non-numeric or more than 2 decimals
400Amount must be greater than zero.amount <= 0
400Note cannot exceed 50 characters.note longer than 50
400Source and destination accounts cannot be the same.same account
403Access denied.source account is not yours
404Account not found.unknown fromAccountId
404Destination account not found.unknown toAccountNumber
422Transfer amount cannot exceed 25,000 EGP per transaction.amount > 25,000
422Account is frozen. Transactions are not allowed.source OR destination is FROZEN
422Daily withdrawal limit of 30,000 EGP exceeded.withdrawals + transfers out today would exceed 30,000
422Insufficient funds.source balance would fall below its floor (0 for SAVINGS, -1,000 for CURRENT)
Request
curl -X POST "http://localhost:8080/api/transfers" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"fromAccountId": 1, "toAccountNumber": "1000000003", "amount": 500, "note": "Rent"}'
Response 200
{
  "referenceId": "#TX-AA310",
  "type": "TRANSFER",
  "accountNumber": "1000000001",
  "amount": 500.0,
  "balanceAfter": 4000.0,
  "dateTime": "2026-10-18 21:40:12"
}
Error example 400
{
  "status": 400,
  "error": "Source account is required."
}

History

GET/accounts/{id}/transactionsCustomer token

Transaction history

Returns the transactions of one of your accounts, newest first, 10 per page. Both date filters are inclusive (a transaction on the To date is included).

Parameters

NameInTypeRequiredRules
idpathintegeryesAccount id (must be yours).
typequerystringnoALL (default), DEPOSIT, WITHDRAWAL, TRANSFER_IN or TRANSFER_OUT.
fromquerystringnoYYYY-MM-DD. Cannot be in the future.
toquerystringnoYYYY-MM-DD. Cannot be in the future, cannot be before from.
pagequeryintegerno1-based page number. Default 1.
  • When nothing matches, the response contains message "No transactions found." and an empty list.

Errors

StatusMessageWhen
400Invalid transaction type.unknown type value
400Invalid date format. Use YYYY-MM-DD.from/to not parseable
400Date cannot be in the future.from or to after today
400From date cannot be after To date.from > to
400Page must be 1 or greater.page < 1
403Access denied.account belongs to another customer
404Account not found.unknown id
Request
curl -X GET "http://localhost:8080/api/accounts/1/transactions?type=DEPOSIT&from=2026-10-01&page=1" \
  -H "Authorization: Bearer <token>"
Response 200
{
  "transactions": [
    {
      "referenceId": "#TX-AA310",
      "type": "TRANSFER_OUT",
      "amount": 500,
      "createdAt": "2026-10-18 21:40:12",
      "balanceAfter": 4000,
      "counterpartyAccount": "1000000003",
      "note": "Rent"
    }
  ],
  "page": 1,
  "totalRecords": 1,
  "totalPages": 1
}
Error example 400
{
  "status": 400,
  "error": "Invalid transaction type."

Errors

Every error uses the same JSON shape:

StatusMeaning
200OK
201Created
400Validation error: the request is malformed or breaks an input rule
401Missing, invalid or expired token (or wrong credentials on login)
403You are not allowed to access this resource
404Resource not found
409Conflict: duplicate or already in that state
422Business rule violation (limits, funds, frozen account)
423Account locked
Error body
{
  "status": 422,
  "error": "Insufficient funds."
}
